# 2.0.0-alpha.5 verification

Verified locally on 2026-09-10 with Corretto 22.0.2 and Gradle 8.14.3 on Windows.

## Build and gameplay

`gradlew.bat build --offline --console=plain` produced all four release JARs. All 34 JUnit tests and 112 Fabric 1.20.1 GameTests passed. New coverage includes:

- Ten distinct bounded module meshes, finite geometry, valid face normals, and emissive/metal materials.
- All 19 decoration blockstates, particle models, and single-item loot tables.
- Actual survival placement and player mining of every part, with exactly one item consumed/returned.
- Creative placement/removal, failed placement against an occupied block, four horizontal rotations, collision bounds, original pick-block item IDs, and zero vanilla luminance.
- Player-slot frame bounds and overlap checks on every powered-emitter page.

Native integration passed on Forge 1.20.1 with Mekanism 10.4.16.80 and NeoForge 1.21.1 with Mekanism 10.7.19.85 (two tests each), plus Fabric 1.21.1 (one test). These checks exercise native part registration, placement/mining/loot, emitter serialization, security, module transfer, and energy delivery. Both Mekanism tests powered the upgraded emitter through Universal Cables. The existing energy and module regression tests remain unchanged.

## Client checks

- Fabric 1.20.1: module and crystal inventory galleries, resource reloads, and the decoration world harness without shaders.
- Forge 1.20.1: decoration world/held-item/resource-reload checks with Oculus 1.8.0, Embeddium 0.3.31, and Kappa_v5.3_Caves. Repeated after the final model corrections.
- Fabric and NeoForge 1.21.1: decoration world/held-item/resource-reload checks with Iris 1.8.8, Sodium 0.6.13, and Kappa_v5.3_Caves. Final shared geometry also compiles on both targets.
- Fabric 1.20.1 and 1.21.1: all 11 English/Russian/compact GUI captures passed their layout assertions.

Screenshots were inspected for model orientation, hollow geometry, lens UV seams, first-/third-person scale, placed block rendering, and colored shader emission. The final module gallery uses front-facing views; lens caps and ring faces share planar UVs. Colored light from placed crystals is visible on the test floor with Kappa. Bloom and surface lighting depend on the shader pack/settings, rather than Minecraft light-block placement.

Screenshots are in each platform's `build/run/clientSmoke/screenshots` folder. Useful captures include `modules-gallery.png`, `ru-energy-compact.png`, `decor-kappa-crystals-night.png`, `decor-kappa-module-hand.png`, and `decor-vanilla-modules-day.png`.

## Scope and artifact audit

The supplied transparent GUI PNG is unchanged. Inventory rows now start at Y=136 with a 20-pixel pitch; the hotbar is at Y=198. Slot frames finish at Y=216, inside the lower contour. The screen dimensions, buttons, and menu behavior were not changed.

The new blocks use the existing item IDs through typed BlockItems. Their block entities are stateless and have no ticker. Placement and mining use the vanilla paths, including creative-mode handling and placement collision checks. Decorations do not run laser effects, consume energy, or add ordinary block light. Module recipes and creative-tab availability still follow technical mode.

The four JARs were checked for 19 decoration blockstates and 19 loot tables each. All 23 existing recipes in each JAR are byte-for-byte identical to alpha.4. No smoke-test/integration classes or Mekanism/Iris implementations are bundled. Comparison against the source backup confirmed no changes to beam rendering, emitter gameplay, energy calculation, existing translations, or GUI artwork.

The previous source tree and four alpha.4 JARs are preserved in `backups/before-module-decor-2.0.0-alpha.4-20260910-133147/`. Reference images, the user's launcher mods, and ordinary game worlds were not changed. All launches used isolated development profiles; release-JAR launcher testing and extended multiplayer testing remain part of the stable-release checklist.
