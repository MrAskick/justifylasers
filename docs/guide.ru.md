<a id="install"></a>
## 1. Установка и ограничения альфы

Для каждой версии Minecraft выпускается свой universal JAR:

- `JustifyLasers-1.20.1-2.0.0-alpha.21-universal.jar`;
- `JustifyLasers-1.21.1-2.0.0-alpha.21-universal.jar`.

Внутри каждого — реализации Fabric, Forge и NeoForge. Установите **один** JAR, подходящий версии Minecraft. Не устанавливайте одновременно универсальный и отдельный loader-specific файл. Universal не означает, что игрок с Fabric может подключиться к серверу Forge: версия Minecraft, загрузчик и версия мода у участников должны соответствовать серверу.

Для Fabric нужен Fabric API; энергетический API Team Reborn включён в сборку. На Forge/NeoForge используется нативный энергетический интерфейс. Architectury API отдельно не требуется. Java: 17 для Minecraft 1.20.1, 21 для 1.21.1. Точные минимальные версии загрузчиков приведены в [README](../README.md#installation).

Mekanism, Jade, JEI и шейдеры необязательны. В текущей промышленной цепочке для обычного выживания полезен совместимый внешний источник энергии: собственные генератор и электроплавильня ещё не закончены. Для лучшего визуального эффекта можно использовать Kappa с подходящим для загрузчика Iris/Oculus. Шейдеры и сторонние моды в JAR не входят.

Что пока не закончено:

- **Структуры с планшетом ещё нет.** Сам планшет и запись схем работают, но получить планшет естественным путём в выживании пока нельзя. Для тестирования нужен Creative или выдача администратором.
- **Fuel Generator и Electric Smelter — WIP.** Блоки работают и сохранены для тестирования/старых миров, но их рецепты отключены.
- **Laser Gun, турель и мечи пока не расходуют энергию, патроны или прочность.** При этом изготовление через сборочник уже требует ресурсов и энергии. Для мечей действует боевая выносливость.
- Альфа не означает завершённую балансировку или проверку со всеми сборками. Сначала сделайте резервную копию мира.

<a id="quickstart"></a>
## 2. Быстрый запуск лазера

Для знакомства в Creative:

1. Откройте вкладку **Justify Lasers** и поставьте **Creative Laser Emitter**. Его можно направить в любую из шести сторон.
2. ПКМ откройте GUI. Выберите цвет, толщину и дальность; при необходимости включите луч.
3. Сначала оставьте урон и разрушение выключенными. Настройки свечения можно менять независимо от них.
4. Поставьте перед лучом кристалл, зеркало, куб или приёмник и проверьте маршрутизацию.

Для **Powered Laser Emitter** дополнительно нужны энергия и установленный цветовой кристалл. Без улучшений его дальность всего **1 блок**, толщина — **0,10×**. Добавьте модули дальности, если луч кажется слишком коротким. Эмиттер, изготовленный в сборочнике, уже содержит кристалл из рецепта.

Редстоун — только управляющий сигнал, не источник питания. По умолчанию он не требуется. Creative-эмиттер не расходует энергию, но и не может создавать её через энергетический приёмник.

<a id="industry"></a>
## 3. Руды и промышленная цепочка

Верхний мир получает две руды, обе с глубинносланцевым вариантом и объёмными минеральными включениями:

| Руда | Где искать | Назначение |
| --- | --- | --- |
| Wolframite / вольфрамит | От низа мира до Y 48; максимум распределения около Y −32. Несколько чаще алмазов | Переплавка в вольфрамитовые слитки для корпусов, оправок и деталей |
| Photonite / фотонит | Глубокие слои, до Y 16; немного реже алмазов | Сырьё для выращивания активного кристалла |

Жилы используют алмазоподобные размеры, включая небольшие, скрытые и редкие крупные варианты. Указанные высоты описывают распределение, а не гарантированную находку. Нужна железная кирка или лучше. **Удача** увеличивает добычу сырья, **Шёлковое касание** возвращает сам рудный блок. Руды появляются только в новых чанках; уже исследованная территория не перегенерируется.

Обычная печь переплавляет один сырой вольфрамит в слиток за **150 секунд**. Ускоренная электроплавильня пока WIP. Сырой фотонит нельзя сразу вставить в эмиттер: сначала его нужно вырастить.

Основная цепочка:

```text
Сырой вольфрамит → печь → слитки → корпуса камер, оправка и детали
Сырой фотонит + кварц + вода + энергия → камера выращивания → фотонитовый кристалл
Фотонитовый кристалл + оправка → белый лазерный кристалл → окрашивание
Пустая схема + заряженный планшет → схема нужной детали/устройства
Схема + материалы + энергия → сборочная камера → готовая деталь/устройство
```

Белый лазерный кристалл можно перекрасить красителем. Доступны девять цветов: красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый, пурпурный и белый. Сборка эмиттера принимает любой из этих кристаллов. Ранее изготовленные цветовые кристаллы остаются пригодными — выращивать их заново не нужно.

Пять базовых компонентов имеют собственные модели, схемы и разные рецепты:

- **Reinforced Laser Housing** — усиленный корпус: вольфрамит и железо.
- **Focusing Lens Assembly** — фокусирующий линзовый узел: стекло, кварц, аметист и вольфрамит.
- **Energy Core** — энергетическое ядро: медь, редстоун, кварц и управляющие схемы.
- **Beam Controller** — контроллер луча: управляющие схемы, компаратор, медь и редстоун.
- **Optical Resonator** — оптический резонатор: линзовый узел, контроллер луча, вольфрамит и кварц.

Не каждое устройство требует все пять деталей. Например, эмиттер собирается из корпуса, резонатора, энергетического ядра и кристалла, а Laser Gun использует линзовый узел вместо резонатора. Точные количества смотрите в JEI и в подсказках требуемых предметов самой камеры. Эти пять компонентов — предметы инвентаря, не декоративные блоки.

<a id="tablet"></a>
## 4. Планшет и схемы

**Extraterrestrial Tablet / Внеземной планшет** — переносной интерактивный каталог. Пока нет структуры с добычей, администратор может выдать его командой:

```mcfunction
/give @s justifylasers:extraterrestrial_tablet
```

Новый планшет разряжен. Ёмкость — **50 000**, зарядка через совместимое зарядное устройство принимает до **256 единиц за один вызов передачи**. Другой способ: возьмите планшет, зажмите Shift и используйте его на доступной Вам запитанной машине мода. Она передаст накопленную энергию в планшет в пределах свободной ёмкости; приватность машины учитывается.

Обычный ПКМ открывает экран прямо в руках. На нём:

- слева — каталог схем;
- справа — реальная 3D-модель выбранного результата, которую можно вращать перетаскиванием мышью;
- игровые часы и фактический процент заряда;
- сведения о выбранной сборке и результат записи.

Колесо мыши и кнопки страниц перелистывают каталог. **Enter** записывает выбранную схему; Escape или клавиша инвентаря закрывает планшет. Разряженный экран сообщает об отсутствии питания.

Пустая схема крафтится на верстаке:

```text
Б Б Б
С Р С
Б Б Б

Б — бумага, С — железный самородок, Р — редстоун
```

Для записи держите пустую схему в инвентаре и оставьте место под результат. Каждая успешная запись расходует **одну пустую схему и 1 000 энергии**. Работа открытого экрана отдельно стоит **1 единицу в тик**, то есть 20 в секунду. Закрытый планшет не расходует заряд на экран. Сервер проверяет заряд, наличие рецепта, пустой карты и места: неудачная запись не должна съедать материалы.

Готовая **Assembly Schematic** многоразовая: сборочник использует её для выбора рецепта, но не расходует при каждой операции. На карточке отображается плоская иконка результата, чтобы отличать схемы друг от друга.

<a id="chambers"></a>
## 5. Мультиблочные камеры и сборка

Для каждой камеры соберите **восемь одинаковых соответствующих корпусов сплошным кубом 2×2×2**, без пустоты внутри. Последний установленный корпус формирует машину; ПКМ также может сформировать уже собранную конструкцию. Нажатие на любую часть открывает общий GUI.

Визуально это большая камера с внутренней рабочей областью. У выращивания видны вода, растущий вращающийся кристалл и электрические разряды. В сборочной камере работают манипуляторы и отображается собираемый предмет. При завершении эмиттера появляется короткий испытательный луч — он только визуальный.

### Камера выращивания

Один цикл по умолчанию:

| Вход | Результат | Длительность | Потребление |
| --- | --- | --- | --- |
| 1 сырой фотонит + 2 кварца + 1 000 мБ воды | 1 фотонитовый кристалл | 600 тиков / 30 секунд | 64/тик, всего 38 400 |

Бак вмещает **8 000 мБ**. Воду можно заливать вёдрами или совместимыми трубами. Она расходуется постепенно; видимый уровень соответствует баку. Вода намеренно полупрозрачная, примерно с 70% непрозрачностью. Готовый голый кристалл ещё требуется объединить с оправкой.

### Сборочная камера

Вставьте схему, затем нужные материалы и обеспечьте питание. В пустых входных слотах показаны полупрозрачные изображения ожидаемых предметов. Если допустимы варианты — например, любой цвет кристалла — изображения по очереди меняются. Это фантомные подсказки, а не выданные предметы.

Есть **26 рецептов сборки**: пять компонентов, эмиттер, оружие, турель, оптические устройства, конфигуратор и модули. У каждого собственные длительность и расход энергии. Например:

| Изделие | Время | Энергия/тик | Всего |
| --- | ---: | ---: | ---: |
| Усиленный корпус | 12 с | 48 | 11 520 |
| Оптический резонатор | 32 с | 176 | 112 640 |
| Powered Laser Emitter | 60 с | 320 | 384 000 |
| Laser Gun | 50 с | 256 | 256 000 |
| LightSaber | 40 с | 192 | 153 600 |
| Light Staff | 70 с | 384 | 537 600 |
| Beam Splitter | 76 с | 416 | 632 320 |
| Refocusing Cube | 80 с | 448 | 716 800 |

Это стоимость одной операции, без предварительного изготовления компонентов. Полная таблица всех 26 рецептов: [assembly-costs.md](assembly-costs.md). Сложным изделиям нужно больше энергии, чем вмещает буфер, поэтому обеспечьте непрерывное питание. Обрыв питания ставит процесс на паузу, а не завершает его бесплатно.

### Автоматизация, редстоун и безопасность

Общий энергетический буфер камеры — **100 000**. Кабели, предметные и водяные трубы можно подключать к любой части сформированного мультиблока **с любой стороны**, включая верх и низ. Предметы поступают во входные слоты, результат доступен на извлечение. Используются Fabric Transfer либо нативные интерфейсы Forge/NeoForge; Mekanism напрямую не требуется.

Справа в GUI есть управление редстоуном и приватностью:

- игнорировать редстоун — по умолчанию;
- работать при наличии сигнала;
- работать при отсутствии сигнала;
- Public / Private — общий доступ либо доступ владельца/администратора.

Сигнал на любой части управляет всей камерой. Private запрещает посторонний доступ и предметную/жидкостную автоматизацию. Это не полноценный территориальный приват. Полный выходной слот, нехватка ресурсов или энергии и запрещающий редстоун ставят обработку на паузу. Инвентарь, вода, энергия и прогресс сохраняются.

Разборка корпуса останавливает мультиблок. Содержимое принадлежит контроллеру и не копируется в каждый корпус. Машина не подгружает отсутствующие чанки автоматически.

<a id="emitter"></a>
## 6. Эмиттер, модули и расход энергии

### Creative и Powered

**Creative Laser Emitter** — исходный неограниченный эмиттер. В техническом режиме его нельзя изготовить легально. У него ручные настройки дальности **1–512 блоков** и толщины **0,10–10,00×**, цвета и возможностей луча. Базовая дальность — 64 блока.

**Powered Laser Emitter** — промышленный вариант. Принимает энергию с любой стороны, имеет буфер **2 000 000** и лимит приёма **100 000 за вызов передачи**. Возможности зависят от установленных деталей. В GUI — модель эмиттера, цветовой индикатор-луч, расход за тик, заряд и причина остановки. Модель можно вращать. Переключение верхних страниц не убирает инвентарь игрока.

Слева находятся модули и два независимых переключателя света, справа — Security и Redstone control. Public разрешает общий доступ; Private ограничивает меню, настройки, перемещение модулей и ломание игроком владельцем/администратором. Энергетический кабель продолжает подавать питание. Взрывы, команды и произвольные изменения мира другими модами этот механизм не защищает.

### Модули Powered-эмиттера

В меню десять слотов: кристалл и девять категорий улучшений. Обычные функциональные модули ставятся по одному; дальность и толщина — стопками до 64.

| Слот | Что даёт |
| --- | --- |
| Кристалл | Цвет луча и модели; без него луч не включится |
| Silk Touch | Шёлковое касание; работает только вместе с включённым дропом |
| Block Drops | Выпадение блоков/предметов и опыта |
| Scorch Marks | Косметические следы на поверхностях |
| Ignition | Поджог сущностей при успешном нанесении урона |
| Block Destruction | Разрушение блоков и доступ к его настройкам |
| Entity Damage | Урон сущностям и доступ к его настройкам |
| Range I / II | Увеличение дальности; два уровня занимают один и тот же слот |
| Thickness | Увеличение толщины луча |
| Target Filter | Выбор категорий целей и исключений |

Разрушение и урон нужно **отдельно включить** в соответствующих подменю после установки модулей. Само наличие модуля не включает опасную функцию. При извлечении способность сразу перестаёт работать, но выбранные настройки запоминаются. Кристаллы и модули не расходуются во время работы.

Дальность считается как `min(512, 1 + количество × бонус уровня)`. Range I даёт +1 блок, Range II — +8; 64 Range II достигают предела 512. Разные уровни нельзя смешать в одной стопке. Толщина растёт по нелинейной шкале от 0,10× без модулей до 10× при 64 модулях. Creative-эмиттер по-прежнему использует слайдеры вместо этих ограничений.

### Цена работающего луча

Цвет, косметическое свечение и наличие целей перед лучом не меняют базовую цену. С установленными настройками энергия списывается каждый серверный тик, пока эмиттер работает.

```text
Расход = 80
       + число Range I + 8 × число Range II + число Thickness
       + [если включено разрушение] 120 × 20^(скорость / 100)
       + [если включён урон] (ударов/сек / 20) ×
         (HP за удар × 40 + отбрасывание × 8 + [если включён поджог] 10)
```

Результат округляется вверх до целого. Коэффициенты меняются в серверном конфиге. Формула использует разрешённые установленными модулями функции.

Примеры без модулей дальности/толщины:

- только красивый луч — **80/тик**;
- разрушение на минимальной скорости — **200/тик**;
- разрушение на максимальной скорости — **2 480/тик**;
- стандартный урон 0,5 HP, 20 ударов/с, отбрасывание 1× добавляет **28/тик**.

64 Range II и 64 Thickness добавляют ещё **576/тик**. Даже последний модуль, выводящий дальность на предел 512, имеет свою цену. Стена на пути сокращает видимый луч, но не отменяет цену установленной дальности. Перенаправление не списывает стоимость заново за каждый сегмент.

Выключенный эмиттер, отсутствие кристалла или запрещающий редстоун не потребляют энергию. При её нехватке останавливаются луч, урон, добыча и активация приёмника. Не путайте запрет работы с обычным упором работающего луча в стену.

При разрушении Powered-эмиттера установленные части выпадают, накопленная энергия теряется. Значения питания, модули и настройки сохраняются при обычном сохранении/перезагрузке мира.

<a id="damage"></a>
## 7. Разрушение блоков и урон

### Разрушение

Настройки доступны через маленькую кнопку у Block Destruction; в Powered-варианте нужен соответствующий модуль.

- **Скорость:** минимум соответствует исходной зависимости от твёрдости блока; максимум — один добытый блок в тик, то есть до 20/с при 20 TPS.
- **Дроп:** переключает предметы и опыт. В Powered-варианте нужен отдельный модуль. Без дропа прямо добытый контейнер также не должен рассыпать содержимое как обход ограничения.
- **Шёлковое касание:** использует обычные Minecraft-таблицы добычи там, где они поддерживаются; требует включённого дропа и своего модуля.
- **Следы:** косметические прожоги, независимые от фактического разрушения.

Предел один блок в тик относится ко **всему эмиттеру**, а не к каждой ветке сплиттера. Неразрушимые блоки остаются преградой. Входная линза редстоун-приёмника защищена от лазерной добычи. Сундуки/шалкеры обрабатывают содержимое с учётом режима дропа; обычные обновления соседних блоков сохраняются.

### Урон сущностям

| Параметр | Диапазон GUI | По умолчанию |
| --- | --- | --- |
| Урон за попадание | 0,1–20 HP | 0,5 HP |
| Частота | 1–20 попаданий/с | 20/с |
| Отбрасывание | 0–10× | 1× |
| Поджог | Вкл./выкл. | Выкл. |

При максимальной частоте луч наносит урон каждый тик. Стандартные 0,5 HP × 20 дают **10 HP/с до защиты**, а не десять сердец. Броня, твёрдость брони, зачарования защиты, Resistance, поглощение, щиты и сопротивление отбрасыванию учитываются. Толщина влияет на зону попадания.

Отбрасывание ограничено и направлено вдоль луча; его можно убрать значением 0. Поджог действует после успешного незаблокированного попадания, до четырёх секунд огня, с учётом огнестойкости/иммунитета. Он не включается при выключенном уроне. В Powered-варианте дополнительно нужен модуль Ignition.

Частоты распределяются по тикам, в том числе не кратные 20. При низком TPS реальные попадания в секунду становятся реже. Фильтр целей запрещает не только урон исключённым сущностям, но и поджог/отбрасывание.

<a id="optics"></a>
## 8. Оптическая сеть

### Кристаллы

Кристаллы можно устанавливать на пол, стены и потолок, а модули и управляющие схемы — как декорации. Чтобы поставить предмет на блок с собственным GUI, используйте Shift + ПКМ. В выживании декорация возвращает тот же предмет без необходимости Шёлкового касания; в Creative лишний дроп не создаётся.

Поставленный кристалл перекрашивает прошедший через него луч. ПКМ переключает **замену цвета** и **аддитивное смешивание**: например, красный плюс синий даёт пурпурный. До кристалла исходный цвет сохраняется, после — идёт изменённый. Цветные грани прозрачные, металлическая оправа непрозрачная; шейдерное свечение не создаёт обычный световой блок Minecraft.

### Зеркало

Laser Mirror крепится к полу, стене или потолку. ПКМ меняет поворот с шагом 15°, Shift + ПКМ — наклон. Отражение определяется настоящей нормалью зеркала. Для точного наведения используйте режим конфигуратора «Aim mirror».

### Beam Splitter

У сплиттера шесть портов: по одному на каждой грани. Конфигуратором задаётся **вход / выход / отключён**. Новый сплиттер имеет один вход и пять выходов.

Входная мощность делится между включёнными выходами: пять выходов — по 1/5, два — по 1/2, один — вся мощность. Выключение всех выходов останавливает ветку. Делятся также урон, отбрасывание, новый поджог, прогресс добычи и передаваемая энергия — сплиттер не умножает их бесплатно.

### Laser Energy Receiver

Это **энергетический**, а не редстоун-приёмник. На каждой грани отдельно назначаются **вход лазера / выход энергии / отключён**. Подведите луч Powered-эмиттера к входу и снимайте энергию кабелем с выходной грани.

По умолчанию возвращается **80% реально оплаченной источником мощности этой ветки**, округлённой вниз. У сплиттеров учитывается доля ветки. Creative-луч может окрасить модель, но даёт **0 энергии**. Поэтому замкнутой сетью нельзя получить вечный источник.

Закрытие выходного порта сразу запрещает извлечение через уже подключённый кабель. При исчезновении луча новые поступления прекращаются, накопленная энергия остаётся доступной на выходах. Автовыдача ограничена общим лимитом `maxInput` в тик на все стороны.

Сплиттер и энергетический приёмник светятся цветом поступающего луча, а без него становятся серыми. При нескольких входах отображается цвет самой сильной ветки; равные входы выбираются стабильно. Свечение наследует настройку эмиттера.

### Общие ограничения

Дальность — бюджет **всего пути**, включая расстояние внутри устройств; каждый поворот не даёт новые 512 блоков. Маршрут не загружает чанки принудительно. Есть защита от циклов, предел 16 перенаправлений и 128 сегментов. Смешанный RGB передаётся по сети; редстоун-приёмник сопоставляет его с ближайшим из девяти цветов.

<a id="receiver"></a>
## 9. Редстоун-приёмник

**Laser Receiver** принимает лазер только передним сенсором, а редстоун выдаёт на остальные пять сторон, в том числе через прилегающие твёрдые блоки. Это отдельный блок от Laser Energy Receiver.

В GUI доступны включение, сила сигнала **0–15**, инверсия, фильтр одного цвета или любого цвета и шейдерное свечение индикаторов. По умолчанию — включён, сила 15, любой цвет, без инверсии.

Обычный режим выдаёт сигнал при подходящем луче; инверсия — при его отсутствии. Общий выключатель всегда убирает выход. Преграда перед сенсором прекращает приём. Поведение не зависит от настроек урона эмиттера. Модель показывает входящий цвет, даже если он не подходит фильтру, и сохраняет последний цвет после прекращения приёма.

<a id="cube"></a>
## 10. Рефокусировочный куб

Куб — физическая сущность с гравитацией и твёрдой коллизией. Он принимает луч с **пяти сторон** и выпускает через **одну**, выделенную двойной рамкой. Светящийся шар с белым ядром, цветовой ореол и индикаторы следуют входящему лучу. Линзы визуально увеличивают сцену; по умолчанию **1,8×**.

| Управление | Действие |
| --- | --- |
| ПКМ по кубу | Взять перед собой / опустить |
| Взгляд при переноске | Направлять выход, в том числе вверх/вниз |
| ЛКМ по кубу | Пнуть; со спринтом сильнее |
| Shift + ПКМ | Повернуть стоящий куб на 90° и выровнять |
| Shift + ЛКМ | Забрать в инвентарь; в Creative удалить |

Куб продолжает принимать и перенаправлять луч в руках. После отпускания выравнивается на ближайшую плоскую грань; учитывает стены и препятствия. Один игрок переносит один куб, один куб нельзя одновременно удерживать нескольким игрокам. После потери носителя или загрузки мира он остаётся свободным объектом.

Выход сохраняет свойства источника: цвет, толщину, урон, частоту, поджог, добычу и свечение с учётом уже разделённой мощности. Попадание прямо в выходную грань не перенаправляется. При конкурирующих входах куб выбирает один стабильным порядком источников; это не смеситель нескольких лазеров. Рецепт куба находится в сборочной камере, не на верстаке.

<a id="configurator"></a>
## 11. Конфигуратор и фильтр целей

Конфигуратор изготовляется по своей схеме в сборочной камере. ПКМ по воздуху меняет режим.

| Режим | Применение |
| --- | --- |
| Rotate / configure ports | ПКМ по грани сплиттера/энергоприёмника меняет режим порта; Shift + ПКМ — в обратную сторону. Эмиттер/редстоун-приёмник поворачивается к выбранной грани |
| Copy settings | Копирует настройки доступного эмиттера и выбирает его для предпросмотра траектории |
| Paste settings | Применяет поддерживаемые настройки к другому доступному эмиттеру |
| Aim mirror | Сначала выберите освещённое зеркало, затем точку назначения; Shift + ПКМ выбирает другое зеркало |

Предпросмотр виден с инструментом в руке для эмиттера под прицелом или ранее скопированного в пределах 64 блоков того же измерения. Он учитывает перекрытие стенами и не наносит урон. Копирование **не переносит** энергию, модули, инвентарь, владельца или приватность; отсутствующие модули нельзя обойти вставкой настроек.

**Target Filter** вставляется в соответствующий слот Powered-эмиттера либо турели. Он независимо разрешает враждебных мобов, мирных существ и игроков; отдельно исключает владельца. До **32 игроков** можно исключить по UUID: введите имя онлайн-игрока и нажмите кнопку добавления/удаления. Повторный ввод уже сохранённого имени снимает исключение, даже если игрок офлайн. Смена имени не отменяет сохранённый UUID.

Извлечение фильтра из эмиттера возвращает обычный нефильтрованный урон; турель без фильтра стреляет только по враждебным мобам. Фильтр не увеличивает мощность и не уменьшает её цену.

<a id="gun"></a>
## 12. Laser Gun и турель

С одним Laser Gun:

- **ЛКМ / Attack** — удерживать для стрельбы;
- **ПКМ / Use** — прицеливаться;
- **Shift + ПКМ** — сменить цвет.

Кнопки следуют переназначениям Minecraft. По умолчанию дальность — **64 блока**, урон — **0,5 HP**, частота — **20/с**, отбрасывание — **1×**. Сервер учитывает защиту цели и препятствия. Луч прекращается на первой подходящей живой цели, столкновении с блоком или границе незагруженного чанка.

Прицел плавно даёт **1,5×** приближение камеры, линза — суммарно **2,5×** относительно обычного обзора. Она использует уже обработанный кадр мира, не вторую полноценную камеру. Поэтому не видит за пределами исходного кадра и не создаёт отсутствующие детали изображения.

В обычном положении есть инерция поворотов, движение при ходьбе/приземлении и опускание на спринте. При прицеливании качание от ходьбы отключается, отдача при стрельбе остаётся. У попаданий в блоки есть остывающие следы; стена за поражённой сущностью не получает след от прошедшего насквозь луча.

**Ограничение:** оружейные лучи пока прямые — не добывают блоки и не используют сеть зеркал/сплиттеров эмиттера. Питание и боеприпасы пока не нужны.

### Турель

Поставьте **Laser Turret Stand** и нажмите ПКМ с Laser Gun, чтобы установить оружие. Следующее взаимодействие открывает инвентарь и управление. Второй слот — Target Filter. Без фильтра турель выбирает только враждебных мобов в пределах **32 блоков**.

Она поворачивается к цели и стреляет при совпадении направления и свободной линии огня. Дружественная сущность впереди перекрывает выстрел. Настройки владельца, цвет, выключатель, оружие и фильтр сохраняются. Настраивать её может владелец либо Creative-игрок.

Извлечение пушки из GUI действительно убирает оружие с модели и прекращает стрельбу. Разрушение стойки возвращает установленную пушку и фильтр без дублирования. Энергия турелью пока не расходуется. И пушка, и стойка собираются по схемам.

<a id="sabers"></a>
## 13. LightSaber, Light Staff и две руки

Мечи работают в основной и второй руке. **LightSaber** — одноклинковый; **Light Staff** — двухклинковый. Свечение рукояти соответствует выбранному цвету клинка.

### Один меч

| Кнопка | Действие |
| --- | --- |
| V | Включить/выключить клинок; можно переназначить |
| ЛКМ | Атака; удержание повторяет удары с учётом фаз и выносливости |
| ПКМ | Фронтальная защита; включает убранный клинок |
| Shift + ПКМ | Сменить цвет |

Без движения одноклинковый меч чередует удар сверху и восходящий; Staff имеет трёхударную последовательность с задействованием второго клинка. Движение вбок задаёт горизонтальные удары, вперёд с боковым движением — диагональные. Если продолжения нет, оружие возвращается в исходное положение.

| Параметр | LightSaber | Light Staff |
| --- | ---: | ---: |
| Урон основной цели до защиты | 6 HP | 6,5 HP |
| Замах / активная фаза / восстановление | 3 / 4 / 5 тиков | 4 / 5 / 6 тиков |
| Выносливость за атаку | 12 | 20 |
| Максимум целей за взмах | 2 | 4 |

Дополнительные цели получают 75% урона. Одну сущность нельзя многократно ударить одним взмахом. Сервер проверяет движущийся клинок в активной фазе; стены прерывают поражение, сетевой спам не ускоряет анимационные интервалы. Учитываются броня, сопротивления, поглощение, щиты и модификаторы атаки.

### Защита, парирование и выносливость

Защита закрывает фронтальный сектор **110°**, но не спину. Поднятая не более чем за **3 тика** до контакта защита даёт парирование: краткий отбой атакующего и возможность более быстрой контратаки с бонусом **15%**. Столкновения клинков сопровождаются отдачей, цветными искрами и звуком.

Начальный запас выносливости — **100**. Обычный блок стоит **18**, парирование — **4**; удержание защиты тоже расходует запас. Истощение ломает защиту. Короткий иммунитет к повторному полному ошеломлению защищает от бесконечного запирания в отдаче. HUD отдельно показывает состояние каждой вооружённой руки. Значения настраиваются сервером.

### Два оружия одновременно

Если в обеих руках находятся оружия мода — два меча, две пушки или смешанная пара:

| Кнопка | Какая физическая рука атакует |
| --- | --- |
| ПКМ / Use | Правая |
| ЛКМ / Attack | Левая |

Это относится именно к видимым левой/правой рукам, в том числе при выбранной леворукости Minecraft. Обе кнопки можно удерживать одновременно; триггеры и атаки независимы. **V** переключает оба удерживаемых меча.

В этом режиме нет общего прицеливания двух пушек и обычного удержания защиты мечом: соответствующие кнопки заняты атаками рук. Чтобы прицелиться, защищаться или поменять цвет через Shift + Use, временно оставьте одно оружие.

Первое лицо использует обычную глубину рук: меч прячется с F1, не переворачивается на крайних углах камеры и не должен уходить в близкую стену вместе с рукой. Следы на поверхностях косметические; мечи пока не являются инструментом добычи.

<a id="visuals"></a>
## 14. Следы, свет, шейдеры и звуки

**Minecraft block light** и **Shader glow** — разные настройки. Первая управляет обычным блочным освещением эмиттера, вторая — эмиссивным материалом луча и цветных деталей. Выключение Shader glow не обязано делать луч невидимым. Цветные отражения и подсветка поверхностей зависят от шейдерпака; собственный аппаратный ray tracing мод не добавляет.

Лучи имеют белое ядро и цветной ореол. Модели оптики, оружия и кристаллов используют согласованные UV и эмиссивные материалы. Для поддержанных линз берётся итоговое изображение сцены после шейдеров. Это эффект экранного преломления/увеличения, а не физическая вторая камера.

Проверенные сочетания Kappa описаны в [README](../README.md#lighting-and-shaders): среди них Fabric/Iris, Forge 1.20.1/Oculus и NeoForge 1.21.1/Iris. Это не обещание совместимости с любым паком. Для Forge 1.21.1 и старого NeoForge 1.20.1 проверенного шейдерного сочетания в этой версии нет.

### Прожоги

Следы оставляют эмиттеры, перенаправленные лучи, Laser Gun и клинки. Движение точки контакта рисует полосу по поверхности. Свежий след яркий, остывает примерно за **2,5 секунды**; тёмный шрам существует около **двух минут** и плавно исчезает в последние 20 секунд.

Следы учитывают реальные поверхности, ступени, плиты и границы блоков. Замена/разрушение опоры убирает след. Они **не сохраняются как повреждение мира**, не меняют твёрдость и дроп, очищаются при смене мира/выгрузке и ограничены по количеству. Включение прожогов не включает добычу. У Powered-эмиттера нужен Scorch Marks; отдельно есть общий клиентский переключатель видимости.

### Звуки

У эмиттеров есть запуск, гул, остановка и контакт. Толщина влияет на высоту и характер звучания. Ближайшие источники приоритетнее, общее число голосов ограничено.

Мечи используют **22 записи OGG**: подбор в руки, пять вариантов гула, девять взмахов, три контакта с поверхностью, отдельные включение и выключение одиночного/двойного меча. Звук столкновения клинков сохранён отдельно.

При запуске голоса случайно выбирается гул, затем он непрерывно зацикливается. Взмахи и контакты выбирают вариант при каждом событии. Каждая рука имеет собственный гул; смена цвета не считается повторным подбором. Длительный прожиг ограничен по частоте звуков, а выключение видимости следов не выключает звук контакта. Перезагрузка ресурсов/снятие mute не должны повторно имитировать включение меча.

## 15. Клиентские настройки и производительность

**J** открывает меню настройки клиента. Клавиша меняется в Minecraft → Управление → Justify Lasers. Сохранение — `config/justifylasers-client.json` при закрытии меню. Эти параметры не меняют серверный урон, дальность, экономику или маршрутизацию.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| Линзы кубов | Включены | Экранное увеличение на гранях |
| Увеличение куба | 1,8×, доступно 1–3× | Сила увеличения |
| Дальность линз | 64 блока, доступно 8–128 | До какого расстояния рисовать эффект |
| Число кубов с линзами | 64, доступно 1–64 | Ограничение тяжёлого эффекта |
| Линза прицела | Включена | Дополнительное увеличение в прицеле; без неё обычное прицеливание остаётся |
| Следы | Включены | Общая видимость косметических прожогов |
| Дальность следов | 96 блоков, доступно 16–128 | Ограничение отрисовки |
| Инерция оружия | Включена | Покачивание; атаки и отдача не отключаются |
| Искры мечей | Включены | Контактные эффекты |
| Громкость | 100% локального множителя | Дополняет общий параметр laserVolume |
| Одновременные звуки | 8, доступно 1–64 | Используется меньший из локального и общего лимитов |

Для насыщенной лазерами сцены сначала уменьшите дальность/число линз и дальность следов. Затем при необходимости выключите линзы кубов полностью: это убирает соответствующие проходы и копирование сцены. Уменьшение количества звуков помогает при множестве источников. Отключение следов очищает уже существующие локальные прожоги. «Сбросить всё» возвращает клиентские значения по умолчанию.

## 16. Конфиг, обновление и диагностика

### Общие настройки

`config/justifylasers.json` создаётся при первом запуске. Для изменения игровых параметров остановите игру/сервер, отредактируйте файл и запустите снова. В сетевой игре урон, экономика и доступность определяются сервером. Отсутствующие новые поля используют значения по умолчанию; существующий файл автоматически не перезаписывается.

Основные группы:

- `energyMode`: `AUTO`, `ON`, `OFF`. При стандартном `industrialProgression: true` промышленный режим включён даже без Mekanism. При `industrialProgression: false` режим AUTO ориентируется на список `technicalMods`. ON принудительно включает энергетику, OFF отключает Powered-эмиттеры и промышленную обработку.
- `capacity`, `maxInput`, `basePerTick`, `miningPerTick`, `miningSpeedMultiplier`, `damagePerHealthPoint`, `knockbackPerHit`, `ignitionPerHit` — экономика эмиттера.
- `energyTransmissionEfficiency` — доля возврата через энергоприёмник; строго больше 0 и меньше 1.
- `machineCapacity`, `machineTransfer`, `crystalGrowerPerTick`, `crystalGrowthTicks`, `crystalTankCapacity`, `crystalWaterPerRecipe` — камеры и вода.
- `assemblyPerTick` и `laserAssemblyTicks` — общие множители мощности и времени рецептов сборки. По умолчанию 160 и 400; индивидуальные цены сохраняют относительные различия.
- `laserGunRange`, `laserGunDamage`, `laserGunHitsPerSecond`, `laserGunKnockback`, `turretRange` — оружие и турели.
- `saberDamage`, `staffDamage`, поля фаз атак, выносливости, блока и парирования — фехтование.
- `laserVolume`, `maxLaserSoundSources` — звук на данном клиенте; они не навязываются сервером.

FE на Forge/NeoForge и E на Fabric здесь используют одинаковые числовые значения. Добавление ID в `technicalMods` только включает обнаружение: сторонний мод всё равно должен реально поддерживать подходящий энергетический интерфейс. Обмен по Mekanism проверялся на Forge 1.20.1 и NeoForge 1.21.1; это не означает проверку всех технических модов.

Рецепты доступны через datapack-тип `justifylasers:industrial`. JEI показывает реальные текущие ингредиенты, схемы, воду, время и расход, включая изменения сборки. Jade отображает энергию, статус и другие краткие сведения; приватные подробности эмиттера скрываются провайдером мода.

### Обновление с alpha.6

1. Скопируйте мир и конфиги в резервную папку.
2. Удалите старый JAR из `mods`, поставьте один новый для своей версии Minecraft и обновите сервер/клиентов согласованно.
3. Сначала проверьте копию мира: эмиттеры, инвентари, редстоун, приёмники и настройки.
4. Для новых руд исследуйте новые чанки. Для тестирования промышленной цепочки обеспечьте источник энергии и доступ к планшету/схемам.

Старые предметы и настройки не должны пропадать. `laser_chassis` и `optical_assembly` заменены усиленным корпусом и линзовым узлом: старые стопки преобразуются при попадании в инвентарь с сохранением количества и пользовательских данных. Старые ID оставлены для совместимости. Старые рабочие эмиттеры не превращаются автоматически в оплачиваемые устройства.

Многие продвинутые рецепты верстака **удалены**: теперь нужны схема и сборочная камера. Это намеренное изменение прогрессии, а не пропавший рецепт. Старые генератор и электроплавильня сохранены как WIP. Universal JAR не гарантирует переносимость данных других модов между загрузчиками; понижение мира с 1.21.1 до 1.20.1 небезопасно.

### Частые вопросы

| Симптом | Что проверить |
| --- | --- |
| Powered-луча нет | Кристалл, заряд, выключатель, редстоун, включённый технический режим и строку статуса |
| Луч очень короткий | Без модулей дальности у Powered только 1 блок; дальше возможны препятствие или незагруженный чанк |
| Не ломает / не дамажит | Нужен соответствующий модуль и отдельно включённая функция; затем фильтр целей и допустимый блок |
| Нет добычи / не работает Silk Touch | Модуль дропа и его переключатель; для Silk Touch нужен ещё его модуль |
| Энергоприёмник даёт ноль | Не Creative-ли источник, правильный ли вход, есть ли оплаченный луч и открытый выход энергии |
| Камера остановилась | Сборку 2×2×2, питание, схему/ингредиенты, воду, место на выходе, редстоун и приватность |
| Нельзя записать схему | Заряд ≥1 000, пустую карту, место в инвентаре и доступный рецепт |
| Планшет нельзя найти | Структура ещё не добавлена; это известное ограничение alpha.21 |
| При двух пушках нет прицела | В двойном режиме обе кнопки отвечают за независимую стрельбу; оставьте одну пушку |
| С шейдерами мало свечения | Совместимость пака/загрузчика, Shader glow и настройки самого шейдерпака |
| Проседает FPS | Дальность/число линз, дальность следов, количество эффектов и параметры шейдеров |

Результаты сборки и тестов, а также оставшаяся проверка перед стабильным релизом: [verification.md](verification.md). При сообщении о баге укажите Minecraft, загрузчик, версию мода, шейдерпак, шаги повторения и приложите подходящий лог без личных данных.
