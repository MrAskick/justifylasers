# 2.0.0 test notes

See [alpha.2 verification](2.0.0-alpha.2-testing.md) for the powered-interface and module update.

Run the Gradle 8.14.3 wrapper with JDK 21 or 22. Local verification used Windows 11, Corretto 22.0.2, and an NVIDIA RTX 5090. Optional compatibility JARs and test worlds are local fixtures, not repository or release contents.

## Regression suite

```text
gradlew.bat build
gradlew.bat test
gradlew.bat runGameTest
```

The default build includes the shared unit tests and Fabric 1.20.1 GameTests. They cover damage mitigation, hit cadence, entity ignition, receivers, range, cube optics/physics/controls, scorch geometry, mining speed and loot, settings, and energy behavior. Renderer geometry tests protect the existing beam and cube profiles.

Reports are in `platforms/fabric-1.20.1/build/test-results/test` and `platforms/fabric-1.20.1/build/gametest-results.xml`.

## Native loader and energy checks

For each target (`fabric-1.20.1`, `forge-1.20.1`, `fabric-1.21.1`, `neoforge-1.21.1`):

```text
gradlew.bat :<target>:runIntegrationTest -PintegrationTests
```

This runs an isolated dedicated test server. The checks exercise registration, recipe conditions, native sided energy ports, simulated transfers, persisted inventory/energy, module restrictions, crystal color, settings validation, actual mining/Silk Touch loot, item returns, and physical cube spawning. They do not require client-only classes on a server.

For the native Mekanism targets, add `-PintegrationModsDir=<absolute-directory>`. That directory must contain a Mekanism JAR for the selected loader and Minecraft version, not multiple versions. A separate test fills a Mekanism creative energy cube, configures its front output, and powers an empty emitter through two Basic Universal Cables. No energy is injected directly into that emitter. The native energy test also verifies that installing Mekanism activates the technical recipes and removes the unlimited emitter recipe.

Verified combinations:

- Forge 47.4.0, Minecraft 1.20.1, Mekanism 10.4.16.80.
- NeoForge 21.1.200, Minecraft 1.21.1, Mekanism 10.7.19.85.

Check the test server's `All ... required tests passed` line under `platforms/<target>/build/run/integrationTest/logs/latest.log`, not just Gradle's exit code: some Forge initialization failures can otherwise exit successfully. Removing a compatibility mod from an existing isolated test world may log missing mappings from its previous run. Never point this harness at a real world.

## GUI and client/server packets

```text
gradlew.bat :<target>:runClientSmoke -PclientSmoke
```

The preview opens the powered emitter's main, modules, mining, and damage pages in English and Russian, including an 854×480 window. It also checks the security and redstone pages. It asserts that visible controls fit and do not overlap, and that all 36 player inventory slots remain visible. Captures are under `platforms/<target>/build/run/clientSmoke/screenshots`; success is `CLIENT_SMOKE_PASSED`.

The world variant, `-PsmokeWorld`, expects a disposable save named `cube-smoke` in that profile's `saves` directory. It changes the test scene near `(200, 3, 204)`, sweeps a powered beam through a cube onto stone/metal surfaces, and captures cooling, hand occlusion, world occlusion, and removed supporting blocks. It then opens the real emitter menu from the integrated server, checks inventory/property/owner synchronization, round-trips a damage-setting payload, and rejects both a stale menu ID and a manual range payload that would bypass modules. It also checks that in-place upgrade stack merges synchronize to the client's world block entity and menu. Success markers are `SCORCH_WORLD_SMOKE_PASSED` and `NETWORK_MENU_SMOKE_PASSED`.

Do not use a valued world as the fixture. The local fixture was copied from the earlier isolated scorch test world; the user's Minecraft installation was not changed.

## Shader scene

Enable Kappa in the isolated profile (`shaderpacks` and `config/iris.properties`, or `config/oculus.properties` on Forge), then run the world smoke test with its shader mods. Visual checks cover the white core, saturated emission/reflections, smooth halo, scorch trails, and depth occlusion.

| Target | Tested rendering mods | Pack |
| --- | --- | --- |
| Fabric 1.20.1 | Iris 1.7.6, Sodium 0.5.13, Indium 1.0.36 | Kappa_v5.3_Caves |
| Forge 1.20.1 | Oculus 1.8.0, Embeddium 0.3.31 | Kappa_v5.3_Caves |
| Fabric 1.21.1 | Iris 1.8.8, Sodium 0.6.13 | Kappa_v5.3_Caves |
| NeoForge 1.21.1 | Iris 1.8.8, Sodium 0.6.13 | Kappa_v5.3_Caves |

For Fabric 1.20.1, use `-PcompatibilityModsDir=<mods-directory>` with the Iris nested runtime libraries under `run/compat-libs`. For the other three targets, use `-PshaderModsDir=<directory>` containing the exact tested filenames. The smoke build extracts nested shader libraries into its own build directory for Loom's development classpath; these are not bundled with Justify Lasers.

The Forge development run needed `mixin.features.render.gui.debug=false` in the isolated profile's `config/embeddium-mixins.properties`. This avoids Embeddium's debug-overlay local-variable capture failing against Loom-remapped ForgeGui. It is a development-classpath workaround, not a Justify Lasers runtime requirement, and is not distributed. Normal-launcher Forge/Oculus testing is still advisable before publishing a stable release.

## Remaining release checks

- Test the remapped release JARs in ordinary launcher profiles, not only Loom's development runs.
- Run a two-machine dedicated multiplayer session and a longer survival session with chunk unload/reload and reconnects.
- Test other energy mods individually before advertising them as verified integrations. The configurable detection list does not itself guarantee their power-network behavior.
- Shader compatibility depends on the shader pack and configuration; these checks are not a guarantee for arbitrary packs or GPU drivers.
